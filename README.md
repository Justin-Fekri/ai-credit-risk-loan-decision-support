# AI Credit Risk & Loan Decision Support System

A binary classification pipeline that estimates loan default risk from borrower
credit history and financial attributes, explains every prediction in plain
language, and presents the result as **decision support for a human underwriter
— never as an automatic approval**.

`Python` · `scikit-learn` · `XGBoost` · `SHAP` · `Explainable AI`

---

## Why this exists

Most credit-risk projects stop at a ROC-AUC score. A lender cannot deploy that.
Lending is a regulated decision that has to be *explained* to the applicant, *audited*
for bias, and *owned* by a person. This project covers the whole path:

| Concern | How it is addressed |
|---|---|
| Is the model any good? | 5-fold CV across three model families, held-out test set, calibration check |
| Do the probabilities mean anything? | Isotonic calibration; Brier score reported |
| Where do we set the cut-off? | Threshold chosen by **expected cost**, not the 0.5 default |
| Why was *this* applicant scored this way? | Per-application SHAP reason codes |
| Is it fair? | Disparate-impact audit against the four-fifths rule |
| Who decides? | Three-band recommendation; every output carries a human-review disclaimer |

> **Note on data.** The default dataset is **synthetic**, generated by a seeded
> model in [`src/credit_risk/data.py`](src/credit_risk/data.py) so the repo runs
> offline with no licensing issues. It is *not* real lending data and this model
> must not be used for real lending decisions. To run on real data, see
> [Using a real dataset](#using-a-real-dataset).

## Quickstart

```bash
git clone https://github.com/<your-username>/credit-risk-loan-decision-support.git
cd credit-risk-loan-decision-support
make setup
```

Then run the whole pipeline:

```bash
make all
```

Or step by step:

```bash
credit-risk generate-data     # build the synthetic dataset
credit-risk train             # cross-validate, select, calibrate, tune threshold
credit-risk evaluate          # metrics, decision bands, fairness audit, plots
credit-risk explain           # global feature importance + SHAP
credit-risk predict --application examples/high_risk_application.json
```

macOS note: XGBoost needs the OpenMP runtime (`brew install libomp`). Without it
the pipeline still runs — that model is skipped and the best of the rest is chosen.

## Results

Held-out test set (2,400 applications, 17.3% default rate):

| Metric | Score |
|---|---|
| ROC-AUC | **0.796** |
| PR-AUC | 0.492 |
| Brier score | 0.114 |
| Recall @ operating threshold | 0.725 |
| Precision @ operating threshold | 0.368 |

Cross-validated model selection — the leaderboard is printed on every run:

| Model | CV ROC-AUC |
|---|---|
| **XGBoost** (selected) | **0.7934** ± 0.0138 |
| Random Forest | 0.7931 ± 0.0143 |
| Logistic Regression | 0.7909 ± 0.0143 |

The three are within one standard deviation of each other. That is the honest
result on this data, and it is why the leaderboard is reported rather than a single
cherry-picked number.

### The decision bands actually separate risk

This is the result that matters for the product — the bands the reviewer sees line
up with real default behaviour:

| Recommendation | Share of portfolio | Actual default rate |
|---|---|---|
| Recommend approve | 71.3% | **8.5%** |
| Manual review | 23.0% | 33.1% |
| Recommend decline | 5.6% | **64.4%** |

A reviewer can safely fast-track the top band and spend their time on the 23% that
genuinely needs judgement.

## What a reviewer sees

```
==========================================================================
  LOAN APPLICATION REVIEW -- APP-DEMO-HIGH
==========================================================================

  Estimated default probability : 99.5%
  Risk band                     : High
  System recommendation         : RECOMMEND DECLINE

  Why the model scored it this way
  ----------------------------------------------------------------------
  1. ^ credit score                 = 561           (increases risk)
  2. ^ debt-to-income ratio         = 0.68          (increases risk)
  3. ^ past delinquencies           = 3             (increases risk)
  4. ^ revolving credit utilisation = 0.94          (increases risk)
  5. ^ length of credit history     = 2.00          (increases risk)

  Next step: High estimated risk. Reviewer to verify before declining.

  ----------------------------------------------------------------------
  DECISION SUPPORT ONLY -- this is a statistical estimate, not an
  approval or a denial. The final lending determination rests with the
  human reviewer, who should weigh information not captured by the
  model.
==========================================================================
```

Probabilities are clipped to [0.5%, 99.5%]: isotonic calibration will otherwise
report a literal "100% chance of default", and no model earns that certainty from a
finite sample.

There is also a Streamlit front-end for the same thing:

```bash
make app
```

## Fairness audit

Run as part of `credit-risk evaluate`, written to `reports/fairness.json`:

```
age_group
  segment                 n   approve   default   DI ratio   flag
  30_to_44              759     65.6%     17.1%       0.79    YES
  45_to_59              712     81.6%     10.5%       0.98
  60_plus               436     83.0%     11.2%       1.00
  under_30              493     28.4%     32.7%       0.34    YES
```

The audit attributes are **never model inputs**. Even so, applicants under 30 are
approved at 34% of the rate of the best-performing group — far below the 0.80
four-fifths threshold — because the model reaches age indirectly through
credit-history length and employment length. The system reports this for human
review rather than silently "correcting" it. See [MODEL_CARD.md](MODEL_CARD.md).

## How it works

```
data.py       synthetic generator (solves for a target default rate)
   |
pipeline.py   impute -> one-hot encode -> [scale] -> estimator, in one sklearn Pipeline
   |
train.py      5-fold CV over 3 models -> pick winner -> isotonic calibration
              -> cost-optimal threshold -> save bundle with full metadata
   |
   +-- evaluate.py   ROC/PR/calibration, cost analysis, decision-band workload
   +-- fairness.py   per-segment approval rates + disparate impact
   +-- explain.py    permutation importance, SHAP global + per-application reasons
   +-- predict.py    score -> risk band -> recommendation -> reviewer summary
```

All preprocessing lives *inside* the Pipeline, so it is fitted on training folds
only and the cross-validation scores stay honest.

**Cost-based thresholding.** Approving a borrower who defaults costs roughly 5x what
declining a good borrower costs, so the threshold minimises `5·FN + 1·FP` rather than
maximising accuracy. Tune it with `--cost-fn` / `--cost-fp`.

## Using a real dataset

```bash
python scripts/download_dataset.py --output data/german_credit.csv
credit-risk train --data data/german_credit.csv
```

This fetches the UCI Statlog (German Credit) dataset — 1,000 real applications — and
maps it onto this project's schema. Verified result: **ROC-AUC 0.802**, in line with
published benchmarks. The script prints exactly which columns are real and which are
derived, because several modern credit fields don't exist in that 1994 dataset.

## Limitations

- **Synthetic data by default.** Results demonstrate the pipeline, not real-world performance.
- **No temporal validation.** Real credit models need out-of-time testing; borrower behaviour drifts.
- **No reject inference.** Trained only on funded loans, the classic credit-scoring selection bias.
- **The fairness audit is a starting point,** not a legal compliance review.
- **Not fit for real lending decisions.**
